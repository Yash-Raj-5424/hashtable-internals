- all the ops in hashmaps are key-based
```
struct Pair{
    void * key;
    int hash_key;
    void * value;   // holds value of any type
}
```
- hashtable would need to have a constructor function for the key as it is accepting any generic type using `void * key` so constructor fuction would provide implementation using the user's desired type
- also, the hashtable must have a destructor function for key and value both so as to remove any memory reference when we delete any key

**implementing hashmap using chained hashtable**
- a hashmap must have <array, size, key_count, comparator_function(key), destructor_fucntion(key), destructor_fucntion(val)>

- we must avoid duplicate keys in the array. so if the key is present, the lookup function would return the value, else it'll return `null`
- to avoid duplicate keys, we use `check and insert`:
1. if key is present already don't insert the key at all
2. if key is present, delete old key and re-insert (it'll bring the key at head of the LL)
3. if the key is present, insert the key without deleting the old key (multiple instances of the same key -> space inefficient) => we're prioritizing fast writes (no lookup for duplicates). in this case, delete would be expensive (since we've to delete all instances)

**implementing hashmap using open adressing hashtables**
- we'll have an array of `slot`
```
struct slot{
    bool is_empty;
    bool is_deleted;    // to check soft deletes
    int32 hash_key; // to avoid recomputation
    void * key;
    void * value;
}
```

- hashmap will contain < array, size, used_slot_count, active_key_count, comparator_function, destructor_function(key), destructor_function(value)>
- during lookup, insert, delete when we find the matching hash_key, we must explicitly compare the keys to check its existence
- destructor should be invoked only when we hard-delete the key/value
